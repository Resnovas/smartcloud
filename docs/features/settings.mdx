title: 'Settings'
description: 'Repository settings as code: merging, features, security, the default branch ruleset, environments, Actions, access, webhooks, Pages and variables.'

A GitHub repository has dozens of settings: which merge buttons are allowed, whether the wiki is on, which checks must pass before merging, who has access, and more. They are usually clicked by hand, one repository at a time, and they drift apart.

The settings feature writes them down instead. You describe the settings you want in the `settings` section, and on every scheduled run smartcloud brings the repository back in line. That gives you:

- **The same baseline everywhere.** Put the settings in a [preset](/glossary#preset) and every repository that extends it gets them.
- **A record of every change.** Settings live in a file, so a change is a reviewed pull request, not a click nobody remembers.
- **Self-healing settings.** If someone changes a setting by hand, the next run puts it back.

Only what you write is changed. A section or key you leave out is never touched, so you can start with one setting and add more later.

<Warning>
  Changing repository settings needs a token with **administration** access to the repository, such as a [GitHub
  App](/glossary#github-app) token. The [workflow token](/glossary#workflow-token) cannot do it. A run with only the
  workflow token, or from a fork or Dependabot, skips settings and says why in the job summary.
</Warning>

## Turn it on

<Steps>
  <Step title="Create a GitHub App (recommended) or a token">
    A GitHub App gives smartcloud short-lived tokens that reach only the repositories you choose, and commits it makes are signed by GitHub.

    1. In your organisation, open **Settings > Developer settings > GitHub Apps > New GitHub App**. Give it a name, set any homepage URL, and untick **Webhook > Active**: smartcloud runs from Actions and needs no webhook.
    2. Under **Repository permissions**, grant what the sections you use need. For every smartcloud feature together that is: Administration (read and write), Contents (read and write), Issues (read and write), Pull requests (read and write), Checks (read and write), Commit statuses (read), Workflows (read and write, for [sync](/features/sync)), Webhooks (read and write, for `settings.webhooks`), Pages (read and write, for `settings.pages`), Environments (read and write, for `settings.environments`) and Variables (read, for `settings.variables`). For `settings.teams`, also grant the organisation permission Members (read).
    3. Create the app, note its **App ID**, and generate a **private key**.
    4. Install the app on the repositories it should manage (and on the repository that holds your presets, if it is private).
    5. In the repository or organisation, add the App ID as an Actions **variable** (for example `SMARTCLOUD_APP_ID`) and the private key as an Actions **secret** (for example `SMARTCLOUD_APP_PRIVATE_KEY`).

    A classic personal access token with the `repo` scope (and `workflow` for sync) can change settings too, but GitHub never lets a personal token create check runs, so every `smartcloud` check fails to publish. Use a GitHub App. Run [`smartcloud doctor`](/cli#doctor) to check a token's scopes and access.

  </Step>
  <Step title="Pass the token to smartcloud">
    Mint a token in the workflow with `actions/create-github-app-token` and give it to smartcloud as `GITHUB_TOKEN`. Keep the fallback to `github.token`, so a run where no token can be minted, such as a pull request from a fork, runs [restricted](/glossary#restricted-run) instead of failing.

    ```yaml .github/workflows/smartcloud.yml
    on:
      push:
        branches: [main]
      schedule:
        - cron: '0 6 * * *'
      workflow_dispatch:

    permissions: {}

    jobs:
      smartcloud:
        runs-on: ubuntu-latest
        timeout-minutes: 75
        permissions:
          contents: write
          pull-requests: write
          checks: write
          issues: write
        steps:
          - name: Mint the app token
            id: app
            # Secrets are not passed to forks or Dependabot, so skip the mint there.
            if: github.event.pull_request.head.repo.full_name == github.repository || !github.event.pull_request
            continue-on-error: true
            uses: actions/create-github-app-token@v3
            with:
              client-id: ${{ vars.SMARTCLOUD_APP_ID }}
              private-key: ${{ secrets.SMARTCLOUD_APP_PRIVATE_KEY }}
              # Without these the token reaches only this repository. Name the
              # repository that holds your preset too if it is private.
              owner: ${{ github.repository_owner }}
              repositories: ${{ github.event.repository.name }},.github
          - uses: resnovas/smartcloud@v2
            with:
              GITHUB_TOKEN: ${{ steps.app.outputs.token || github.token }}
    ```

    Pin actions to a full commit SHA in a real workflow. The settings feature runs on `schedule`, `workflow_dispatch` and `push` events only.

  </Step>
  <Step title="Add a settings section">
    Start small. This turns off merge commits and deletes branches after merging:

    ```yaml .github/smartcloud.yml
    settings:
      merging:
        mergeCommit: false
        deleteBranchOnMerge: true
    ```

  </Step>
  <Step title="Preview, then run">
    See what would change before anything is written with [`smartcloud plan settings`](/cli), the MCP server's `plan_settings` tool, or a run with the `dryRun: true` input. Then run the workflow from the **Actions** tab (**Run workflow**), or wait for the schedule.
  </Step>
</Steps>

## Options

Every key is optional. A key left out is left as GitHub has it.

### `merging`

| Key                           | Default   | What it does                                                                             |
| ----------------------------- | --------- | ---------------------------------------------------------------------------------------- |
| `merging.mergeCommit`         | unchanged | Allow the **Create a merge commit** button.                                              |
| `merging.squash`              | unchanged | Allow **Squash and merge**.                                                              |
| `merging.rebase`              | unchanged | Allow **Rebase and merge**.                                                              |
| `merging.autoMerge`           | unchanged | Allow auto-merge, so a pull request merges by itself once its checks and reviews pass.   |
| `merging.updateBranch`        | unchanged | Always suggest updating a pull request branch that is behind its base.                   |
| `merging.deleteBranchOnMerge` | unchanged | Delete a pull request's branch once it merges.                                           |
| `merging.webCommitSignoff`    | unchanged | Require sign-off on commits made in the GitHub web editor.                               |
| `merging.squashTitle`         | unchanged | The squash commit's title: `PR_TITLE` or `COMMIT_OR_PR_TITLE`.                           |
| `merging.squashMessage`       | unchanged | The squash commit's body: `COMMIT_MESSAGES` (keeps every trailer), `PR_BODY` or `BLANK`. |

smartcloud reads the repository's current settings first and leaves out any value it already has, because GitHub refuses some writes even of an unchanged value (sign-off an organisation enforces, or a wiki toggle the token may not make). A repository that already matches gets no update.

### `features`

| Key                     | Default   | What it does                         |
| ----------------------- | --------- | ------------------------------------ |
| `features.wiki`         | unchanged | Turn the repository wiki on or off.  |
| `features.discussions`  | unchanged | Turn GitHub Discussions on or off.   |
| `features.sponsorships` | unchanged | Show or hide the **Sponsor** button. |

### `security`

| Key                                      | Default   | What it does                                                                                                                                                      |
| ---------------------------------------- | --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `security.immutableReleases`             | unchanged | Published releases cannot be changed or have their assets replaced.                                                                                               |
| `security.privateVulnerabilityReporting` | unchanged | Let people report vulnerabilities privately. Public repositories only; on a private one a notice says it was not changed.                                         |
| `security.dependabotAlerts`              | unchanged | Turn on the dependency graph with Dependabot alerts.                                                                                                              |
| `security.dependabotSecurityUpdates`     | unchanged | Let Dependabot open pull requests that fix alerts. Needs `dependabotAlerts`, so turn both on together.                                                            |
| `security.codeScanning`                  | unchanged | `default` or `extended` turn on CodeQL default setup with that query suite. `off` turns default setup off, which advanced setup (your own CodeQL workflow) needs. |
| `security.secretScanning`                | unchanged | `true` or `false` for secret scanning, push protection, Copilot secret detection and non-provider patterns together. Public repositories only.                    |

Secret scanning is only changed on public repositories. On a private one it needs a paid Advanced Security licence, so smartcloud leaves it to the organisation and records a notice. Code scanning fails when the repository has no language CodeQL supports, and secret scanning can fail too; both are reported as warnings rather than errors.

### `ruleset`

`ruleset` manages one [ruleset](/glossary#ruleset) on the default branch. A ruleset is GitHub's modern branch protection: rules such as "no force pushes" or "these checks must pass" that apply to a branch. smartcloud finds its ruleset by `name` and updates it in place on every run.

<Note>
  The ruleset is written whole. A rule you leave out, or switch off, is not enforced, even if someone added it by hand.
</Note>

| Key                                                       | Default                 | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------- | ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ruleset.name`                                            | `house: default branch` | The ruleset's name, which is how smartcloud finds it again.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ruleset.blockDeletion`                                   | off                     | The branch cannot be deleted.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `ruleset.blockForcePush`                                  | off                     | No force pushes.                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ruleset.linearHistory`                                   | off                     | No merge commits on the branch.                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `ruleset.mergeQueue.method`                               | `squash`                | How the [merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue) merges: `squash`, `rebase` or `merge`. Left out, it squashes, or uses `rebase` (then `merge`) when `pullRequest.mergeMethods` does not allow squash. Must fit the rest of the ruleset; see [The merge queue method must fit the ruleset](#the-merge-queue-method-must-fit-the-ruleset). |
| `ruleset.mergeQueue.grouping`                             | GitHub's (`allGreen`)   | `allGreen`: every queued entry must pass the required checks. `headGreen`: only the head of each group must.                                                                                                                                                                                                                                                                                                                                                     |
| `ruleset.mergeQueue.checkTimeoutMinutes`                  | GitHub's (60)           | Minutes a queued entry may wait for checks, 1 to 360.                                                                                                                                                                                                                                                                                                                                                                                                            |
| `ruleset.mergeQueue.maxEntriesToBuild`                    | GitHub's (5)            | Entries built at once, 0 to 100.                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `ruleset.mergeQueue.minEntriesToMerge`                    | GitHub's (1)            | Fewest entries merged together, 0 to 100.                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `ruleset.mergeQueue.maxEntriesToMerge`                    | GitHub's (5)            | Most entries merged together, 0 to 100.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ruleset.mergeQueue.minEntriesToMergeWaitMinutes`         | GitHub's (5)            | Minutes to wait for `minEntriesToMerge` entries, 0 to 360.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `ruleset.requiredDeployments`                             | none                    | Environments the branch must deploy to successfully before merging, for example `[Staging]`. Leave it out if the repository does not deploy.                                                                                                                                                                                                                                                                                                                     |
| `ruleset.signedCommits`                                   | off                     | Every commit pushed to the branch is signed and verified.                                                                                                                                                                                                                                                                                                                                                                                                        |
| `ruleset.pullRequest.requiredApprovals`                   | `0`                     | Approvals needed, 0 to 10. Applies only once two or more distinct [maintainers](/glossary#maintainer) are listed in `roles.maintainers`; before that no approval is required, so a sole maintainer is never blocked.                                                                                                                                                                                                                                             |
| `ruleset.pullRequest.dismissStaleReviews`                 | `false`                 | A new push dismisses earlier approvals.                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `ruleset.pullRequest.codeOwnerReview`                     | `false`                 | A code owner must approve changes to files they own.                                                                                                                                                                                                                                                                                                                                                                                                             |
| `ruleset.pullRequest.lastPushApproval`                    | `false`                 | Someone other than the person who pushed last must approve.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ruleset.pullRequest.conversationResolution`              | `false`                 | Every review conversation must be resolved before merging.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `ruleset.pullRequest.extraApprovalForUnattributedCopilot` | `false`                 | One more approval when Copilot opens a pull request on no one's behalf. No effect with zero approvals.                                                                                                                                                                                                                                                                                                                                                           |
| `ruleset.pullRequest.mergeMethods`                        | all three               | The merge methods allowed: any of `squash`, `rebase`, `merge`.                                                                                                                                                                                                                                                                                                                                                                                                   |
| `ruleset.statusChecks.checks`                             | none                    | Required checks, as a map of check name to `true`. A map, not a list, so a preset and a repository can each add checks.                                                                                                                                                                                                                                                                                                                                          |
| `ruleset.statusChecks.strict`                             | off                     | Branches must be up to date with the base before merging.                                                                                                                                                                                                                                                                                                                                                                                                        |
| `ruleset.statusChecks.skipOnCreation`                     | off                     | A new branch may be created even if a check would block it.                                                                                                                                                                                                                                                                                                                                                                                                      |
| `ruleset.requiredChecks`                                  | none                    | An older list of required checks that binds only once two or more distinct maintainers are listed. Prefer `statusChecks`; a check in both is required once.                                                                                                                                                                                                                                                                                                      |
| `ruleset.codeScanning.<tool>.securityAlerts`              | required per tool       | Security alerts from this code scanning tool (`CodeQL`, `ESLint`, ...) that block merging: `none`, `critical`, `high_or_higher`, `medium_or_higher` or `all`.                                                                                                                                                                                                                                                                                                    |
| `ruleset.codeScanning.<tool>.alerts`                      | required per tool       | Other alerts that block merging: `none`, `errors`, `errors_and_warnings` or `all`.                                                                                                                                                                                                                                                                                                                                                                               |
| `ruleset.codeScanningGate`                                | off                     | Shorthand for CodeQL at `high_or_higher` and `errors`. It wins over a `codeScanning.CodeQL` entry, so a repository cannot weaken a gate its preset turns on.                                                                                                                                                                                                                                                                                                     |
| `ruleset.codeQuality`                                     | none                    | GitHub Code Quality results at this severity or above block merging: `errors`, `warnings`, `notes` or `all`. Code Quality must be enabled on the repository.                                                                                                                                                                                                                                                                                                     |
| `ruleset.codeCoverage.enabled`                            | off                     | Enforce the coverage limits below. Off by default, because they need coverage uploaded with `actions/upload-code-coverage`, so a preset can set limits and each repository switch them on.                                                                                                                                                                                                                                                                       |
| `ruleset.codeCoverage.minimum`                            | none                    | Minimum line coverage, in percent (0 to 100).                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `ruleset.codeCoverage.maxDrop`                            | none                    | Largest drop in line coverage from the default branch, in percentage points (0 to 100).                                                                                                                                                                                                                                                                                                                                                                          |
| `ruleset.secretScanningAlerts`                            | none                    | Open secret scanning alerts of these types block merging, for example `[provider_patterns]`. A GitHub preview rule.                                                                                                                                                                                                                                                                                                                                              |
| `ruleset.copilotReview`                                   | off                     | Copilot reviews every pull request, drafts included, on every push.                                                                                                                                                                                                                                                                                                                                                                                              |
| `ruleset.adminBypass`                                     | `true`                  | Repository admins may bypass the ruleset. Set `false` to remove the bypass.                                                                                                                                                                                                                                                                                                                                                                                      |

Only list a code scanning tool under `codeScanning` if it uploads results for every pull request, or nothing can merge. Every workflow behind a required check must also run on the `merge_group` event when you use a merge queue. On a private repository, rulesets need a paid plan, so a ruleset failure there is a warning.

```yaml
settings:
  ruleset:
    blockForcePush: true
    pullRequest:
      requiredApprovals: 1
      mergeMethods: [squash]
    statusChecks:
      checks:
        smartcloud: true # the aggregate check from the required feature
        test: true
      strict: true
```

#### The merge queue method must fit the ruleset

A [merge queue](https://docs.github.com/en/repositories/configuring-branches-and-merges-in-your-repository/configuring-pull-request-merges/managing-a-merge-queue) lines pull requests up and merges them one group at a time, using `mergeQueue.method`. Two other rules limit which methods can work, and a queue whose method breaks either of them can never merge anything:

- **`linearHistory: true` rules out `merge`.** Linear history means the branch has no merge commits, and the `merge` method makes one for every pull request. GitHub would refuse every merge the queue tries.
- **`pullRequest.mergeMethods` must include the queue's method.** That list says which ways a pull request may be merged. A queue told to `rebase` while pull requests may only be squashed is asking for something the same ruleset forbids.

smartcloud checks both once your config and its [presets](/presets) are merged, because the conflict often comes from two places: the house preset turns on linear history, and your own config asks the queue to `merge`.

What you will see:

- **`smartcloud validate`** (and the MCP `validate_config` tool) fails and names the key, for example `["mergeQueue"]["method"]: the merge queue cannot use merge while linearHistory is on, because a merge commit breaks linear history; use squash or rebase`, or `the merge queue method rebase is not one of pullRequest.mergeMethods (squash); add it there or use one of them`.
- **A run never breaks for it.** It ignores the method, uses one that fits instead (squash, or the first of rebase and merge that the ruleset allows), and reports a `config.ignored` warning on the `smartcloud / config` check, naming the file and `settings.ruleset.mergeQueue.method`.
- **`smartcloud plan settings`** (and the MCP `plan_settings` tool) shows the ruleset with the method it will really use, and lists the ignored method under "Ignored, so not applied".

To fix it, pick a method that fits, or leave `method` out and let smartcloud pick one:

```yaml
settings:
  ruleset:
    linearHistory: true
    mergeQueue:
      method: squash # not merge: linear history forbids merge commits
    pullRequest:
      mergeMethods: [squash, rebase] # includes the queue's method
```

### `environments`

| Key                        | Default | What it does                                                                             |
| -------------------------- | ------- | ---------------------------------------------------------------------------------------- |
| `environments.projectType` | none    | Picks a standard set of deployment environments: `saas`, `desktop`, `library` or `none`. |
| `environments.names`       | none    | The environments to create. Wins over `projectType`.                                     |

| `projectType` | Environments                                                |
| ------------- | ----------------------------------------------------------- |
| `saas`        | Production, Staging, Development                            |
| `desktop`     | Windows, Linux, macOS, Windows Beta, Linux Beta, macOS Beta |
| `library`     | Release                                                     |
| `none`        | none                                                        |

Environments that ship to users deploy only from the default branch and from release tags matching `v*`. smartcloud sets them to use custom deployment branch policies and creates a branch policy for the default branch and a tag policy for `v*` when they are missing; policies you added yourself are kept. It does not rely on GitHub's "protected branches" option, because that counts only classic branch protection, and with none (this feature writes a ruleset instead) every branch could deploy. Staging, development, dev, preview and any name ending in "Beta" accept any branch.

### `actions`

| Key                                        | Default   | What it does                                                                                                                                                        |
| ------------------------------------------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `actions.enabled`                          | unchanged | Whether GitHub Actions runs in the repository.                                                                                                                      |
| `actions.allowedActions`                   | unchanged | Which actions may run: `all`, `local_only` (the organisation's or account's own) or `selected`.                                                                     |
| `actions.shaPinningRequired`               | unchanged | Every action must be pinned to a full commit SHA.                                                                                                                   |
| `actions.selectedActions.githubOwned`      | unchanged | With `allowedActions: selected`: allow actions GitHub owns.                                                                                                         |
| `actions.selectedActions.verifiedCreators` | unchanged | With `allowedActions: selected`: allow actions from verified creators.                                                                                              |
| `actions.selectedActions.patterns`         | unchanged | With `allowedActions: selected`: allow actions matching these patterns, such as `Resnovas/*`.                                                                       |
| `actions.workflowPermissions`              | unchanged | The default permissions of the workflow token: `read` or `write`.                                                                                                   |
| `actions.createPullRequests`               | unchanged | Let the workflow token create and approve pull requests.                                                                                                            |
| `actions.accessLevel`                      | unchanged | Which other repositories may use this one's actions and reusable workflows: `none`, `user`, `organization` or `enterprise`. Private and internal repositories only. |

GitHub needs `enabled` whenever `allowedActions` or `shaPinningRequired` is sent, so setting either alone keeps Actions on. `selectedActions` is ignored unless `allowedActions` is `selected`, because GitHub rejects it otherwise.

The access level only exists for private and internal repositories: any repository can already use the actions of a public one. On a public repository it is left alone and a notice says so. Keep it at `organization` on a private repository whose reusable workflows the others call, such as a private `.github` repository; at `none`, every workflow that calls them fails before it starts.

Set `workflowPermissions: read` only when every workflow declares the `permissions` it needs. A workflow that relies on the default write access breaks.

### `collaborators` and `teams`

| Key                     | Default | What it does                                                                                                                                        |
| ----------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `collaborators.<login>` | none    | Give a GitHub user a role: `read`, `triage`, `write`, `maintain` or `admin`. Someone who is not a collaborator yet is invited. `none` removes them. |
| `teams.<slug>`          | none    | Give an organisation team a role from the same list (not `none`). A team without access is added.                                                   |

Only the logins and teams you list are changed; everyone else keeps their access. Teams can only be given access, not removed: remove one by hand.

### `webhooks`

`webhooks` maps a name of your choosing to a webhook. smartcloud finds the webhook on GitHub by its `url`.

| Key                           | Default                    | What it does                                           |
| ----------------------------- | -------------------------- | ------------------------------------------------------ |
| `webhooks.<name>.url`         | required                   | The payload URL, starting `https://` or `http://`.     |
| `webhooks.<name>.events`      | `[push]` for a new webhook | The events that trigger it.                            |
| `webhooks.<name>.contentType` | unchanged                  | `json` or `form`.                                      |
| `webhooks.<name>.active`      | unchanged                  | `false` stops deliveries without deleting the webhook. |
| `webhooks.<name>.insecureSsl` | unchanged                  | `true` skips TLS certificate checks. Leave it off.     |

smartcloud never sets or changes a webhook secret: add one by hand in the webhook's settings, and later runs keep it. Plans and reports name only the URL's host, but the config itself is readable by everyone who can read the repository, so keep tokens out of the URL on a public repository.

### `pages`

| Key                   | Default             | What it does                                                                               |
| --------------------- | ------------------- | ------------------------------------------------------------------------------------------ |
| `pages.enabled`       | `true`              | `false` unpublishes the site.                                                              |
| `pages.buildType`     | `workflow` when new | `workflow` (an Actions workflow deploys it) or `legacy` (GitHub builds it from a branch).  |
| `pages.branch`        | the default branch  | The branch a `legacy` site builds from. Ignored for `workflow`.                            |
| `pages.path`          | `/`                 | The folder a `legacy` site builds from: `/` or `/docs`. Ignored for `workflow`.            |
| `pages.cname`         | unchanged           | The custom domain.                                                                         |
| `pages.httpsEnforced` | unchanged           | Redirect HTTP to HTTPS. GitHub rejects it until the custom domain's certificate is issued. |

A missing site is created (built from a workflow unless a branch, path or `legacy` build type is set), then updated with the custom domain and HTTPS setting. An existing site is updated with what the config sets.

### `variables`

`variables` maps each Actions variable the repository must have to a sentence saying what it is for. smartcloud only checks that the names exist. Values are never read, written or kept in the config. A missing variable is a warning that names it and its purpose, so a maintainer can add it by hand under **Settings > Secrets and variables > Actions > Variables**. Names compare ignoring case, since GitHub stores them in upper case, and names starting with `GITHUB_` are reserved by GitHub and rejected by the schema.

```yaml
settings:
  variables:
    DEPLOY_URL: Where the site deploys, read by the release workflow.
```

## Complete example

```yaml .github/smartcloud.yml
version: 2

roles:
  # Two or more maintainers make ruleset approvals and requiredChecks bind.
  maintainers: [octocat, hubot]

settings:
  merging:
    mergeCommit: false
    squash: true
    rebase: false
    autoMerge: true
    updateBranch: true
    deleteBranchOnMerge: true
    webCommitSignoff: true
    squashTitle: PR_TITLE
    squashMessage: COMMIT_MESSAGES # keeps Signed-off-by trailers
  features:
    wiki: false
    discussions: true
    sponsorships: false
  security:
    immutableReleases: true
    privateVulnerabilityReporting: true
    dependabotAlerts: true
    dependabotSecurityUpdates: true
    codeScanning: default
    secretScanning: true
  ruleset:
    linearHistory: true
    blockDeletion: true
    blockForcePush: true
    mergeQueue:
      method: squash
      grouping: allGreen
    requiredDeployments: [Staging]
    signedCommits: true
    pullRequest:
      requiredApprovals: 1
      dismissStaleReviews: true
      conversationResolution: true
      extraApprovalForUnattributedCopilot: true
      mergeMethods: [squash, rebase]
    statusChecks:
      checks:
        smartcloud: true
        check: true
      strict: true
      skipOnCreation: true
    codeScanning:
      CodeQL: { securityAlerts: high_or_higher, alerts: errors }
    codeQuality: errors
    codeCoverage:
      enabled: true
      minimum: 80
      maxDrop: 5
    secretScanningAlerts: [provider_patterns]
    copilotReview: true
  environments:
    projectType: saas # Production, Staging, Development
  actions:
    workflowPermissions: read
    createPullRequests: true
    accessLevel: organization
  collaborators:
    hubot: write
  teams:
    docs: triage
  webhooks:
    chat:
      url: https://hooks.example.com/smartcloud
      events: [release]
      contentType: json
  pages:
    buildType: workflow
  variables:
    DEPLOY_URL: Where the site deploys.
```

## How it works

1. The feature runs on `schedule`, `workflow_dispatch` and `push` events. Other events never change settings.
2. smartcloud reads the repository, then plans one step per configured part, in a fixed order: merging, features, security, the ruleset, environments (each followed by its deployment policies), Actions, collaborators, teams, webhooks, Pages, then the variables check.
3. Each step is applied on its own. A failed step is reported and the others still run.
4. Some steps are expected to fail on some repositories, so their failure is a warning rather than an error: code scanning (no supported language), secret scanning, the ruleset on a private repository (rulesets need a paid plan there), and missing Actions variables.

The push limit (**Settings > General > Pushes**) has no API, so every run records a notice to set it by hand. Webhook secrets and Actions variable values are also set by hand.

## What you will see on GitHub

- A `smartcloud / settings` [check run](/glossary#check-run) on the commit. It fails when a required step failed (for example a token without administration access), is neutral when only optional steps failed, and passes otherwise. Every run carries the `settings.push-limit` notice.
- In the job summary, one change per step that was applied, such as `Ruleset "house: default branch"` or `Collaborator @hubot as write (invited if not yet a collaborator)`, and each failure with GitHub's message, under a rule id like `settings.ruleset` or `settings.collaborator:octocat`.
- On GitHub itself: the ruleset under **Settings > Rules > Rulesets**, named `house: default branch` unless you set `ruleset.name`, environments under **Settings > Environments**, and invitations for new collaborators.

## Forks and restricted runs

Settings only ever runs with a token that can administer the repository. In a [restricted run](/reporting#restricted-runs), which is any run with only the workflow token, a pull request from a fork, or Dependabot's runs and pull requests, the feature is skipped and the job summary says "repository settings need an admin token". Scheduled and manually dispatched runs never come from a fork, so they get your app token whenever it can be minted.

## In the house preset

The Resnovas [house preset](/presets) sets a full baseline: squash and rebase merges only, auto-merge, branch deletion and web sign-off on, squash commits titled from the pull request with every commit message kept; wiki off, discussions and sponsorships on; immutable releases, private vulnerability reporting, Dependabot alerts and security updates and secret scanning on, and CodeQL default setup off (the house runs CodeQL as advanced setup); a `house: default branch` ruleset with deletion and force-push blocked, linear history, a squash merge queue with `allGreen`, signed commits, one approval with stale reviews dismissed and conversations resolved, the `smartcloud` check required with `strict`, CodeQL at `high_or_higher`/`errors`, code quality at `errors`, coverage limits of 80 and 5 (off until enabled), provider secret alerts, Copilot review and admin bypass; and read-only workflow tokens that may open pull requests, with organisation access.

A repository extending it may still add what the preset leaves unset: `settings.environments`, `ruleset.requiredDeployments`, extra `ruleset.statusChecks.checks`, `ruleset.codeScanning.ESLint`, `ruleset.codeCoverage.enabled`, `collaborators`, `teams`, `webhooks`, `pages` and `variables`. It cannot change a value the preset sets; see [Add, never change](/presets#add-never-change).

## Troubleshooting

<AccordionGroup>
  <Accordion title="The job summary says settings was skipped: restricted access">
    The run had only the workflow token, or came from a fork or Dependabot. Mint a GitHub App token as `GITHUB_TOKEN`, as in [Turn it on](#turn-it-on), and run the workflow on a schedule or by hand. `smartcloud doctor` shows whether your token can administer the repository.
  </Accordion>
  <Accordion title="Every step fails with Resource not accessible by integration or 403">
    The token has no administration write access to this repository. For a GitHub App, add **Administration: read and write** and accept the new permissions on the installation. For a classic token, add the `repo` scope. For a fine-grained token, add Administration (write).
  </Accordion>
  <Accordion title="Code scanning or secret scanning fails with a warning">
    Code scanning default setup needs a language CodeQL supports. Secret scanning on a private repository needs Advanced Security, so smartcloud does not change it there and records a notice instead. Both are warnings, so the check does not fail.
  </Accordion>
  <Accordion title="A required approval is not enforced">
    `ruleset.pullRequest.requiredApprovals` and `ruleset.requiredChecks` only bind once two or more distinct logins are in `roles.maintainers`, so a sole maintainer is never locked out. Add a second maintainer.
  </Accordion>
  <Accordion title="Nothing can merge after adding code scanning or coverage rules">
    A `codeScanning` tool or `codeCoverage.enabled: true` blocks merging until results are uploaded for every pull request. Upload them (CodeQL workflow, `actions/upload-code-coverage`) or remove the rule. With a merge queue, every workflow behind a required check must also run on `merge_group`.
  </Accordion>
  <Accordion title="ignored settings.ruleset.mergeQueue.method">
    The merge queue's method conflicts with the rest of the ruleset: it is `merge` while `linearHistory` is on, or it is not in `pullRequest.mergeMethods`. The run used a method that fits instead. Change `mergeQueue.method` to one that fits, or leave it out; see [The merge queue method must fit the ruleset](#the-merge-queue-method-must-fit-the-ruleset). If a preset sets both values, fix the preset.
  </Accordion>
  <Accordion title="A missing variable warning">
    `settings.variables` lists a name that is not set. Add it by hand under **Settings > Secrets and variables > Actions > Variables**; smartcloud never writes values.
  </Accordion>
  <Accordion title="cannot change settings.... it is set by a preset">
    Your config gives a different value for a setting your preset already sets. Presets are locked: remove the value from your config, or change the preset. See [Presets](/presets).
  </Accordion>
</AccordionGroup>
