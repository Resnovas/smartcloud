title: 'Introduction'

smartcloud is a GitHub Action that automates repository housekeeping and enforces contribution policy from one declarative file, `.github/smartcloud.yml`. It labels pull requests and issues, checks titles and commits, gates reviews, marks inactive work stale, locks long-closed threads, backports merged pull requests by label, turns on auto-merge where a rule allows it, keeps repository settings in line, syncs shared files from a template repository, notifies Slack, Discord or Linear of policy failures and stale items, and answers slash commands in comments.

## What it can do

| You want to...                                                          | Feature                                  |
| ----------------------------------------------------------------------- | ---------------------------------------- |
| Keep a set of labels in every repository, and label items automatically | [Labels](/features/labels)               |
| Check pull request and issue titles and descriptions                    | [Conventions](/features/conventions)     |
| Require DCO sign-off and honest AI attribution on commits               | [Commits](/features/commits)             |
| Require an AI disclosure in pull request descriptions                   | [Disclosure](/features/disclosure)       |
| Require maintainer approvals, request reviewers, approve trusted bots   | [Reviews](/features/reviews)             |
| Require one check that waits for every other check                      | [Required](/features/required)           |
| Stop merging during a release or holiday freeze                         | [Freeze](/features/freeze)               |
| Enforce branch names                                                    | [Branches](/features/branches)           |
| Generate and check `CODEOWNERS`                                         | [CODEOWNERS](/features/codeowners)       |
| Mark quiet issues and pull requests stale, then close them              | [Stale](/features/stale)                 |
| Lock old closed threads                                                 | [Lock](/features/lock)                   |
| Backport merged pull requests to release branches by label              | [Backport](/features/backport)           |
| Manage repository settings, rulesets, environments and secrets as code  | [Settings](/features/settings)           |
| Keep shared files in line with a template repository                    | [Sync](/features/sync)                   |
| Tell Slack, Discord or Linear about failures and stale items            | [Notifications](/features/notifications) |
| Let people run `/label`, `/rebase`, `/backport` and more in comments    | [Commands](/features/commands)           |

Each capability is a feature with its own section in the config. A feature whose section is absent does not run, so you opt in to exactly what you need. You can also build on a shared config, called a [preset](/presets), so many repositories follow the same rules.

The rest of this page is a reference for the workflow: the permissions, the action's inputs and which events run which features. [Getting started](/getting-started) walks through it from the beginning.

## Permissions

| Permission             | Why smartcloud needs it                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `contents: write`      | The sync, codeowners and backport features push a branch with synced, generated or backported files. Reading presets and templates needs at least `read`.                            |
| `pull-requests: write` | Labels, review requests, automatic approvals, auto-merge, backport pull requests and the report comment on pull requests.                                                            |
| `checks: write`        | One check run per feature on the commit.                                                                                                                                             |
| `issues: write`        | Labels, stale and lock comments, locking conversations, and the report comment on issues. Repository labels are managed through this permission too.                                 |
| `statuses: read`       | For the [required](/features/required) and [freeze](/features/freeze) features, and when a rule uses `checksPass` or `checkStatus`: they read commit statuses as well as check runs. |

The settings feature changes repository administration settings, which the workflow token cannot do. See [Settings](/features/settings).

Grant these on the job and leave the workflow's `permissions` empty, so a job added later starts with no access. `timeout-minutes` stops a hung run long before GitHub's six-hour default, and leaves room for the aggregate check, which waits up to `required.timeout` (60 minutes by default) for the other checks.

<Note>
  A run with only the workflow token is restricted rather than failed: smartcloud skips settings, sync, private presets
  in other repositories and every write GitHub refuses, and lists them in the job summary. Pull requests from forks, and
  Dependabot's runs and pull requests (even when a person reviews them), are always restricted, whatever token the
  workflow passes; see [Restricted runs](/reporting#restricted-runs).
</Note>

## Action inputs

Every input is optional.

| Input           | Default                                                                                 | What it does                                                                                                                                                                                                                                                                                                                                                 |
| --------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GITHUB_TOKEN`  | `${{ github.token }}`                                                                   | The token smartcloud acts with. Settings, sync and private presets in other repositories need a stronger token than the workflow token.                                                                                                                                                                                                                      |
| `workflowToken` | `${{ github.token }}`                                                                   | The workflow's own token. Leave it at its default: smartcloud compares `GITHUB_TOKEN` with it to tell a [restricted run](/reporting#restricted-runs), acts with it on forks and Dependabot runs, and reads the pull request's checks with it for the required feature, since `GITHUB_TOKEN` can be a personal access token without checks and statuses read. |
| `config`        | the first of `.github/smartcloud.yml`, `.github/smartcloud.yaml`, `.github/config.json` | The config file's path in the repository.                                                                                                                                                                                                                                                                                                                    |
| `configJson`    | none                                                                                    | The config given inline, as YAML or JSON. Wins over the file.                                                                                                                                                                                                                                                                                                |
| `configRef`     | the default branch                                                                      | The branch, tag or commit to read the config from.                                                                                                                                                                                                                                                                                                           |
| `dryRun`        | `false`                                                                                 | Record every write in the job summary instead of making it.                                                                                                                                                                                                                                                                                                  |
| `features`      | every configured feature                                                                | A comma-separated list of the features to run, for example `labels,stale`.                                                                                                                                                                                                                                                                                   |
| `checkRunId`    | none                                                                                    | The job's own check run, as `${{ job.check_run_id }}` gives it. The [required](/features/required) feature runs only when it is set, so it can wait for every other check and leave this job out.                                                                                                                                                            |
| `telemetry`     | `true`                                                                                  | Set to `false` to stop sending anonymous telemetry. Discouraged; see [Telemetry](/telemetry).                                                                                                                                                                                                                                                                |

The config is read through the GitHub API, so the workflow needs no checkout step. It comes from the default branch unless `configRef` says otherwise, so a pull request cannot loosen the rules it is checked against.

The run fails when any finding is an error or a feature fails to run. Any other failure, such as a missing config, is one error annotation, never a stack trace.

The v1 inputs `fillEmpty` and `skipDelete` are still accepted and ignored with a warning. See [Migrating from v1](/migration).

## Which events run which features

| Event                                                                                       | Features                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pull_request`, `pull_request_target`, `pull_request_review`, `pull_request_review_comment` | labels (labelling and size labels), conventions, commits, disclosure, reviews, required, freeze (the check), branches, codeowners (the check), sync (the edit check), automerge, backport and commands (backports on merge; `pull_request` and `pull_request_target` only) |
| `issues`                                                                                    | labels (labelling), conventions                                                                                                                                                                                                                                            |
| `issue_comment`, on an issue or a pull request                                              | commands                                                                                                                                                                                                                                                                   |
| `push`                                                                                      | labels (label sync), settings, sync, codeowners                                                                                                                                                                                                                            |
| `schedule`, `workflow_dispatch`                                                             | labels (label sync), stale, lock, freeze (refreshes the check on open pull requests), settings, sync, codeowners                                                                                                                                                           |
| `merge_group`                                                                               | labels (label sync), freeze (fails a queued group during a freeze)                                                                                                                                                                                                         |
| `repository_dispatch`                                                                       | labels (label sync)                                                                                                                                                                                                                                                        |

Any other event is a clean no-op that records a notice. A comment carries only the issue fields of the item it is on, so a comment runs only the [commands](/features/commands) feature; the other features act on the pull request and issue events. [Notifications](/features/notifications) are sent after any run whose results match the configured channels.
